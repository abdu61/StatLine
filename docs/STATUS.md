# Status

**Milestone:** M3 complete (tier 1) · M4 complete · M5/M6 in progress ·
**Updated:** 2026-10-24

## Where it stands

The strip is a parented child of `Shell_TrayWnd`, the flyout opens and closes cleanly,
and the per-app breakdown is in: clicking the strip shows the busiest processes by CPU
share and working set, and the companion window shows the same table. The process query
only runs while one of those surfaces is open.

```
strip hosted by Shell_TrayWnd (tier 1)
strip 237x42 at (1348,1028) presented=true tier=child
detail sampling on
```

## Working

- **Strip**: network first, then CPU / MEM / GPU / DISK with meters, hover plate per
  segment, right-click menu, parented into the taskbar (`WS_CHILD`), `WM_MOUSEACTIVATE`
  suppressed, hides for fullscreen and a hidden taskbar, recreates after an Explorer
  restart via the app message window. Topmost popup remains as an automatic fallback.
  Network leads so its varying rate text changes the strip's left edge instead of
  shifting the other segments. Rates use three significant digits with a reserved
  segment width, so neither digits nor units move the strip. Placement reads
  `TaskbarAl`: **Right** anchors to the tray; **Left** uses the far-left free area on a
  centred taskbar, or the space after the app-button group when the taskbar is
  left-aligned (so it never overlays Start or the app buttons).
- **Flyout**: opens on strip click, toggles closed on a second click, closes on Esc or
  focus loss. A segment click shows only that module — CPU with per-core bars and the
  CPU process table, Memory with commit/cache and top memory apps, Disk with volumes,
  Network with adapters — plus System and Battery. Charts use the accent and turn
  warning yellow / critical red as a value approaches its limit. It is created at its
  final anchored rect and re-anchors upward when the process table arrives. With Mica
  on, the panel is lightly translucent.
- **Companion**: framed resizable window with a left nav (Dashboard, CPU, Memory, GPU,
  Disk, Network, Battery, System, Settings, About). Module pages show a labelled
  per-core grid (percentage and clock) plus 1/5/15-minute averages and processes;
  memory cache and top memory apps; per-volume and per-adapter rows. `Ctrl+Tab` cycles
  pages, `Ctrl+1..9` jumps, `Ctrl+S` opens settings. Its position and size are
  remembered in `window.json` and restored only when still on a monitor. Optional Mica
  DWM backdrop on the framed windows. The shell has a LIVE chip, an accent rule under
  page titles, outlined cards and an accent marker on the active nav item.
- **Settings**: a framed window from the tray menu, the strip menu, or the companion nav,
  with theme, accent presets, sampler interval, byte units, Mica, strip placement,
  start-with-Windows and per-module strip visibility. Mica shows a GPU/battery caution.
  Changes apply live and are saved atomically to `%APPDATA%\StatLine\settings.json`;
  unknown keys are ignored.
- **Packaging**: portable zip script (exe, README, changelog, privacy/access docs,
  licence texts) and an MSIX manifest with `runFullTrust` + a user-toggleable startup
  task. Both build locally; CI verifies fmt/clippy/test/deny/build and produces tag
  artifacts. A multi-size icon is embedded in the exe and the tiles are regenerated by
  `scripts/make-icon.ps1`.
- **Per-app breakdown**: `NtQuerySystemInformation(SystemProcessInformation)` with CPU-time
  deltas; Task Manager scale (share of all cores); instances of the same executable are
  grouped into one row with the instance count in the label, plus live thread counts;
  `—` until a baseline exists; sampled at 2 s only while the flyout or companion is open
  (~4.75 ms per query).
- **Sensors**: ACPI "System" temperature via PDH (5 s), drive temperatures via
  `IOCTL_STORAGE_QUERY_PROPERTY` (5 min cache, volume → disk mapping), battery health,
  temperature and cycle count via `IOCTL_BATTERY_QUERY_INFORMATION` (30 s). GPU vendor
  telemetry rides the 3 s GPU cadence: NVML for NVIDIA, ADL PMLog/Overdrive5 for AMD
  (temperature, fan, power, clocks). Every source degrades to hidden; they share the
  process table's surface-visibility gate.
- **CPU detail**: current load plus 1/5/15-minute exponentially smoothed averages
  computed from real elapsed time, a labelled core grid with each core's percentage and
  clock from `CallNtPowerInformation`, the registry processor name and nominal base clock.
- **Memory detail**: commit/cached plus aggregate page-file (swap) usage from
  `SystemPageFileInformation`, all converted from pages to bytes.
- **Disk detail**: aggregate read/write and per-volume used/total, temperature, plus
  per-physical-disk rates and busy percentage from named PDH instances (`Disk 0 C:`),
  and each drive's bus type and model (`NVMe SAMSUNG MZVLQ512HALU-00000`) from
  `StorageDeviceProperty` on a zero-access handle. Raw capacity and
  `IOCTL_STORAGE_PREDICT_FAILURE` need administrator access, so capacity is summed from
  volumes and no health badge is invented.
- **Network detail**: only real interfaces (NDIS filter miniports are excluded), with
  per-adapter rates, session totals, the negotiated link speed
  (`MIB_IF_ROW2.TransmitLinkSpeed`, e.g. "Wi-Fi · 866 Mbps") and, on WLAN, the SSID and
  signal quality from `wlanapi` (queried only while a detail surface is open).
- **System detail**: Windows edition/build (corrected to "Windows 11" from the build
  number, since ProductName still says Windows 10 on many builds), computer name, process
  count, and every populated memory slot with capacity, DDR generation and configured
  speed from SMBIOS type 17 (`GetSystemFirmwareTable('RSMB')`), read once at the first
  system sample and skipped in safe mode. The bank locator rides the value because laptop
  firmware repeats the device locator for both SODIMMs.
- **Tray tooltip**: one line mirroring the strip (`CPU 23% · MEM 57% · …`), rebuilt from
  the same segments, so the values stay readable while a fullscreen app hides the strip.
- **GPU detail**: whole-GPU utilization and VRAM, plus per-app GPU share parsed from the
  PID in each `\GPU Engine(*)` instance name — no vendor SDK, works on an APU. The GPU
  page's process table answers "which app is using the GPU"; the top-N cut ranks by the
  larger of CPU and GPU share so a GPU-heavy app is not dropped on an idle CPU.
- **DPI**: process is per-monitor-v2 aware. The strip re-reads the taskbar DPI each tick
  and rebuilds its surface when the scale changes; the companion handles
  `WM_DPICHANGED` with the suggested rectangle and re-renders at the new scale.
- **Sampling**: 243 µs per `Sampler::sample` in a tight loop with detail providers off;
  WS ~30 MB, private ~15 MB, handles flat over an hour (338–342). `--bench` uses the
  median wall sample time (mean/p95 include scheduler preemption). **Visible** idle cost
  with the strip on screen is 0.39 % of one core — higher than the 0.2 % target, and that
  is Direct2D drawing, documented in [`adr/0006`](adr/0006-strip-repaint-cost.md).
  Tray-only measures 0.000 %.
- **Lifecycle**: single instance, autostart commands, 1 MB × 3 log rotation, panic hook,
  `--tray-only`. Startup is a per-user `Run` value that only a release `statline.exe`
  may write; debug builds and test harnesses are refused, stale paths are repaired, and
  `--startup-status` reports the exact command. No elevation.
- **Access**: first-run tray notification, an Access/Writes/Startup block in About,
  `docs/ACCESS.md`, `PRIVACY.md`, and `docs/PUBLISHING.md`. The MSIX declares only
  `runFullTrust` plus a disabled-by-default startup task.

## Next, in order

1. **Settings complete**: theme, interval, units, temperature, density, strip order,
   per-module visibility, Mica and start-with-Windows all apply live. `--safe-mode`
   remains a CLI flag rather than a Settings row.
2. **Sensors out of reach**: CPU package/per-core temperature and fan RPM need a kernel
   driver; GPU vendor telemetry is implemented (NVML/ADL), so an NVIDIA machine is only
   needed to exercise that path.
3. **Packaging, remaining**: the local `v0.1.0` tag. The one-hour soak (125 samples,
   handles 338–342, WS 25.9–33.1 MB) and `--bench 120` are recorded in
   `docs/ops/perf-log.md`, `cargo deny check` is green, and both the portable zip and the
   MSIX build. Signing and the final Store identity are human steps.
4. **Polish**: empty states, multi-monitor, per-pixel blur behind the flyout (needs a
   composition swapchain). `--safe-mode` and `--reset-settings` exist as diagnostics.
   Verified: a native `tooltips_class32` will not pop for a stacked/child layered window
   of `explorer.exe`, even with `TTF_TRACK` + `TTM_TRACKACTIVATE`, so the strip has no
   hover tooltip; the flyout carries the same information on click. The **tray icon's**
   tooltip does mirror the strip, which is what stays reachable while a fullscreen app
   hides the strip itself.

## Measured

| Mode | WS | Private | Handles |
|---|---|---|---|
| `--tray-only` | 10.6 MB | 1.8 MB | 145 |
| strip live, parented (tier 1) | 30.0 MB | 14.5 MB | 314 |
| companion + process table | 38.9 MB | 17.9 MB | 374 |

The process table query costs 4.75 ms for ~250 processes; at the 2 s cadence and only
while a process surface is open that is ~0.24 % of one core, and zero when closed.
Handles and private bytes are flat across companion open/close cycles. Sensors are gated
the same way: the idle tight-loop sample is 0.46 ms, and opening a detail surface raises
the average to ~2.3 ms/sample (process table dominates).
